# ADR: dsh-ai-terminal и dsh-trading — копировать, форкать или вливаться

Дата: 2026-11-06. Статус: **принято (вариант D); шлюз — здесь, коннектор с 2026-11-09 — в [`kmlebedev/dshtrading-connector-transaq`](https://github.com/kmlebedev/dshtrading-connector-transaq)**. Срез dsh-trading:
`b3c9b96` (2026-11-06), клон только для чтения, код не запускался.

## Контекст

[zhu1090093659/dsh-trading](https://github.com/zhu1090093659/dsh-trading) — AI-терминал на
той же платформе DeepSeek Harness (тот же baseline **0.2.2-rc.1**, Cordis), созданный 2026-08-30.
Наш `dsh-ai-terminal` — DSH-плагин с одной main-панелью, который проксирует Go-бэкенд
`cmd/terminal` поверх собственного `native/` (TRANSAQ без DLL).

## Сравнение (факты)

| | **наш dsh-ai-terminal + terminal/ + native/** | **dsh-trading** |
|---|---|---|
| Язык / объём | Go ≈ 30 k строк `native/` + ≈ 40 k `terminal/`; JS-плагин 4,3 k | TypeScript-монорепо, 61 пакет, ≈ 128 k строк, 327 тест-файлов |
| Рынки | MOEX (Finam/TRANSAQ) | crypto, US, CN, HK, фьючерсы КНР; **RU нет** |
| Коннекторы | 1, но протокол восстановлен целиком: 45/45 команд, без DLL/Wine | 22 пакета `connector-*`, в основном REST-обёртки публичных API; брокерские (QMT, Futu, Longbridge, Tiger, IBKR) по их же README **без подтверждения на живой сети** |
| Интеграция в DSH | iframe/прокси одного SPA из Go | нативно: Cordis-плагины, client-ui-* пакеты, роли агентов, пресеты, settings-роутинг провайдеров |
| AI-слой | встроенный tool-calling loop, бэктест, walk-forward/deflated Sharpe/PBO, research-batch, ClickHouse-рекордер, paper/rule-боты | мульти-агентная команда (master/researcher/trader/risk), скиллы-чеклисты, `strategy_backtest`, база знаний |
| Безопасность ордеров | live off by default, `ErrOutcomeUnknown`, без авто-повтора `RQ_TRANSACT` | dry-run по умолчанию, `intentId`-идемпотентность, Ed25519 «authority» + approval, fail-closed headless |
| Деньги | `model.Decimal` | `number` (float) в `OrderRequest`/`Ticker` |
| Лицензия | в репозитории **нет LICENSE** (по умолчанию все права у автора) | **PolyForm Noncommercial 1.0.0** |
| Сообщество | — | 300★, 36 форков; фактически один автор (54/54 коммита в клоне), из внешних PR влит 1 |
| Язык документации | русский | китайский (README есть на английском) |

### Что важно для решения

1. **Лицензия PolyForm NC.** Любой скопированный кусок кода или форк можно использовать только
   некоммерчески, и это условие перейдёт на наш проект. Идеи и архитектурные приёмы лицензией не
   защищены — их можно переписывать с нуля (clean-room).
2. **Технологии не совпадают.** Их ценность — TS/React-UI и Cordis-обвязка; наша — Go-ядро
   протокола. Копировать TS в Go-бэкенд нечего, а наш Go в их монорепо не встаёт.
3. **Реестр провайдеров открыт, а список рынков закрыт.** `MarketDataRegistry`/`TradeRegistry`
   принимают любой `market`/`provider` («新市场 = 新键»), но в роутере
   (`packages/router/src/catalog.ts:18,433`), `base` (presets, market-tools, research-tools),
   `bot-api/bridge.ts` и ≈ 6 файлах `client-ui-trading` перечислены жёстко
   `crypto|us|cn|hk|futures|global`. Сторонний пакет может зарегистрировать сервис `ru/finam`,
   но вкладки MOEX в GUI без правки их ядра не появится.
4. **Их модель брокерского коннектора совпадает с нашей архитектурой.** `connector-qmt` и
   `connector-futu` — тонкие TS-адаптеры к **локальному шлюзу** (`gatewayUrl`). Наш `cmd/terminal`
   уже является таким шлюзом (loopback, токен API, `/api/*`).
5. **Скорость апстрима.** Один автор, десятки коммитов в неделю, китайские комментарии: форк будет
   постоянно отставать, и сливать изменения обратно будет дорого.

## Варианты

| Вариант | Плюсы | Минусы | Оценка |
|---|---|---|---|
| A. Копировать их код к себе | быстрые UI-фичи | NC-лицензия переходит на наш проект; TS в Go-бэкенд не встаёт | ✗ |
| B. Форк dsh-trading + наш коннектор внутри | сразу получаем их UI, роли, мульти-рынок | NC навсегда, 128 k строк чужого TS на поддержку, постоянный rebase за одним быстрым автором | ✗ |
| C. Влить коннектор в апстрим | охват 300★, их GUI для MOEX | нужна правка ≈ 10 файлов ядра (закрытый список рынков), нужен maintainer; наш адаптер уйдёт под NC; апстрим почти не принимает внешние PR | ◐ только после согласования |
| **D. Своё ядро + внешний адаптер** | Go-ядро остаётся нашим под любой лицензией; один и тот же шлюз обслуживает наш терминал и dsh-trading; форк не нужен | работа над тонким TS-пакетом и стабильным API шлюза | ✔ |

## Решение (рекомендация)

**D, с C как необязательным вторым шагом. Не копировать и не форкать.**

1. **Ядро остаётся нашим.** `native/` + `cmd/terminal` — продукт; лицензию выбрать явно и
   сейчас (сейчас её нет). Если допускается коммерческое использование — Apache-2.0/MIT для
   `native/` или dual-license.
2. **Стабилизировать API шлюза** `cmd/terminal` как контракт брокерского шлюза в духе
   `connector-qmt`: ticker, klines + capabilities, orderbook, trades, instruments, positions,
   balances, open orders, fills, place/cancel/get order с `intentId`. Цены отдавать **строками
   Decimal**, во float переводить только в адаптере.
3. **`@<scope>/dshtrading-connector-transaq`** — отдельный TS-пакет в нашем репозитории или
   отдельном репо под нашей лицензией. Сгенерировать структуру по образцу их
   `connector-template` (сам шаблон под NC: повторить структуру по описанию, не копировать файлы).
   Он регистрирует `ru/finam` в их реестрах, чтобы агент dsh-trading работал с MOEX через свои
   инструменты уже без правок ядра.
4. **Открыть issue в dsh-trading** с предложением сделать список рынков открытым (из реестра,
   а не литералов) или принять рынок `ru`. Если maintainer согласен — небольшой PR в ядро
   (вариант C). Наш коннектор при этом остаётся внешним пакетом, и NC на него не распространяется.
5. **Перенести идеи, а не код** (clean-room, в Go):
   - журнал идемпотентности `intentId` для `neworder` (совместим с `ErrOutcomeUnknown`);
   - отдельный «authority»-план для live-торговли (подпись разрешения, а не только флаг/env);
   - `klineCapabilities` и роутинг источников по глубине истории;
   - роли агента (researcher / trader / risk-reviewer) и чеклист риска перед заявкой как скилл;
   - CI-гейты (`live-order:check`, `tool-contract:check`) как Go-тесты/скрипты.

## Что не проверено

- dsh-trading не собирался и не запускался; совместимость адаптера с их загрузчиком — **I**.
- Готовность maintainer принимать рынок RU и внешние коннекторы не выяснялась.
- Юридическая оценка — краткое прочтение текста PolyForm NC 1.0.0, не консультация юриста.
