# Отпечатки исполняющих роботов в ленте стакана

Дата: 2026-11-06. Ветка: `plan/ai-terminal-a`. Задача плана: **Task 17** (Phase E).
Статусы фактов: **S** — проверено на демо-сервере, **O** — оракул DLL, **D** — декомпилятор,
**I** — вывод/не проверено. Все выводы этой задачи получены на **синтетической** ленте; живой записи
`md.book_events`/`md.trades` в этой задаче не было, поэтому признаки и пороги — **I** и подлежат
подтверждению на реальной записи.

Пакет: [`terminal/fingerprint`](../../terminal/fingerprint/detectors.go); тесты —
[`fingerprint_test.go`](../../terminal/fingerprint/fingerprint_test.go); инструмент агента —
`detect_execution_algos` в [`terminal/agent/tools_research.go`](../../terminal/agent/tools_research.go).

## 1. Контракт

```go
type Footprint struct {
    Kind       string             // twap|vwap|pov|iceberg|margin_liquidation|unknown_algo
    Symbol     string
    Side       string             // buy|sell (у unknown_algo — пусто)
    From, To   time.Time          // окно анализа, в котором найден паттерн
    Confidence float64            // [0,1]; ниже Config.MinConfidence не репортится
    Evidence   map[string]float64 // значения признаков, на которых построен Confidence
}

func Detect(ctx context.Context, events []lobreplay.Event, cfg Config) []Footprint
func Synthesize(kind string, base []lobreplay.Event, params map[string]float64, seed int64) []lobreplay.Event
```

`Detect` — детерминированный: без часов, сети и рандома; карта `Evidence` сериализуется с
отсортированными ключами. Окно анализа — `Config.Window` (default 60 с), шаг — `Config.Step`
(default 60 с, то есть окна не перекрываются). Окно с числом сделок меньше `Config.MinTrades`
(default 30) не анализируется. Отменённый `ctx` останавливает проход и возвращает уже найденное
(сигнатура без ошибки зафиксирована планом).

`Synthesize` — генератор ground truth: вставляет в реальную/синтетическую ленту известный алгоритм и
возвращает новую ленту, отсортированную по времени. Параметры — `map[string]float64` (сигнатура
плана): `startMs`, `clips`, `qty`, `intervalMs`, `jitterMs`, `side` (0 buy/bid, 1 sell/ask),
`price`, `cycles`, `levelQty`, `eatQty`, `qtyStep`, `stepPct`, `ratio`. Вставленным сделкам
выдаются номера после последней базовой сделки.

## 2. Признаки и детекторы

Все цены — `model.Decimal` в scaled units `Decimal64(6)`; ни один признак не переводит цену в
`float64` (float появляется только в dimensionless-метриках: доли, энтропия, корреляции).

### 2.1 TWAP — `twap`
- **Клипы:** мода размера сделки на стороне агрессора, `modeShare = modeCount / trades`,
  `clip_count = modeCount`, `MinClips = 5`; нормированная энтропия размеров — в Evidence.
- **Периодичность:** межсобытийные интервалы серии одинаковых клипов. `interval_regularity` — доля
  интервалов в ±25% от медианного (устойчивость к одной случайной сделке того же размера);
  пик нормированной автокорреляции presence-серии с шагом `BinSize = 250 мс`;
  пик спектра (DFT по целым периодам от `MinPeriod = 300 мс` до `MaxPeriod = 30 с`).
- **Счёт:** `clipScore * countFactor * (0.45*interval_regularity + 0.30*autocorr + 0.25*spectral)`.
  Перемножение важно: перемешанная лента сохраняет размеры клипов, но теряет расписание, поэтому
  не проходит порог (Review Focus ложных срабатываний).
- `interval_cv` считается только по inlier-интервалам; `median_interval_ms` — медиана.

### 2.2 VWAP — `vwap`
Корреляция Пирсона темпа (объём на sub-bucket, `VWAPBuckets = 12`) с модельным внутридневным
профилем объёма `intradayVolumeWeight(t)`: U-образный профиль сессии 10:00–18:40 МСК (высокий на
открытии и закрытии). Гейт: минимум `MinVWAPTrades = 80` сделок стороны, иначе «расписание» из
десятка сделок не считается. Формула профиля — **I**.

### 2.3 POV — `pov`
Стабильность доли стороны в объёме рынка по sub-bucket-ам: `share_mean`, `share_cv`. Гейт —
`MinPOVTrades = 80`; низкий CV и осмысленная доля (>2%) дают Confidence.

### 2.4 Айсберг — `iceberg` (нужен L2)
По видимым обновлениям уровня: уровень уменьшился, **в течение `RefillWindow = 2 с`** восстановился
до ≥90% прежнего размера, и рядом с этим моментом по этой цене прошла сделка (в окне
`[уменьшение - RefillWindow, восстановление]`). Считаются циклы на одной цене; нужно ≥3 циклов.
Книжная сторона переводится в сторону скрытого игрока: bid → `buy`, ask → `sell`.
Отмена+восстановление без сделки (не айсберг) не считается. Книга записи при этом не мутируется,
используются только записанные level-события.

### 2.5 Маржин-колл — `margin_liquidation`
Серия агрессивных **продаж** внутри известного окна брокерских маржин-коллов:
`sell_share` объёма, `size_growth` = относительный рост среднего размера продаж во второй половине
окна против первой, `price_decline` = падение VWAP-цены между половинами окна.
Confidence = 0.30*sellShare + 0.35*sizeGrowth + 0.35*priceDecline (каждый — с порогом).

Окна маржин-коллов задаются конфигом `MarginCallWindows []string` в формате `"HH:MM-HH:MM"` **МСК**
(UTC+3, без перехода на летнее время; зона фиксированная, tzdata не нужен). Значения по умолчанию —
`14:00-14:30` и `18:00-18:30` МСК — **I**: гипотеза о кластеризации принудительных закрытий в
начале послеобеденной и вечерней сессии; на реальных данных она должна подтверждаться отчётами
брокеров/риск-службы. Невалидные строки окон игнорируются (опечатка не должна отключать анализ).
Никакой другой детектор не срабатывает вне окон: это временной гейт, снижающий ложные срабатывания
на произвольной ленте.

### 2.6 Неизвестный алгоритм — `unknown_algo`
DBSCAN (собственная реализация в [`cluster.go`](../../terminal/fingerprint/cluster.go)) по
стандартизованным (z-score) признакам окон, которые не объяснены известными детекторами:
лог числа сделок, `sell_share`, энтропия и mode-share сторон, автокорреляции и CV интервалов,
VWAP-корреляции, `price_decline`. Параметры: `DBSCANEps = 0.45`, `DBSCANMinPoints = 5`; кластеризация
запускается только при ≥2*minPoints необъяснённых окон (иначе данных мало для кластера). Confidence
кластера = 0.30 + 0.30*cohesion + 0.10*sizeFactor (≤0.7): это «похожие окна», а не идентификация.

## 3. Ограничения и честность атрибуции

- В анонимной ленте **нет `orderno`** и идентификатора участника: атрибуция вероятностная.
  `Footprint` — это паттерн, а не обвинение; `Confidence` обязателен, `Evidence` позволяет
  проверить вывод вручную. Формулировки вида «это точно робот X» недопустимы.
- Порог репортинга `MinConfidence = 0.6`; всё, что ниже, не попадает в результат.
- `From/To` — окно анализа, в котором найден паттерн, а не точные границы работы робота.
- Iceberg требует записанных level-событий (L2) в окне; на одной ленте сделок он не детектируется.
- Порядок replay — по `ts` записи (см. Task 14): кросс-фидовый лаг `quotes`/`alltrades`
  не реконструируется, поэтому границы окон вероятностные.
- DBSCAN на короткой записи (<10 окон) не запускается.
- Всё вышеперечисленное проверено только на синтетике; живой записи не было (**I**).

## 4. Синтетический ground truth и тесты

Тесты строят детерминированную фоновую ленту (снимок книги + ~1,2 случайных сделки/с на обе стороны
+ редкие обновления уровней) и вставляют через `Synthesize` известный алгоритм:

| Тест | Что проверяет |
|---|---|
| `TestDetectsSyntheticTWAP` | recall ≥ 80% на 20 seeds: 20 клипов по 25 ед. каждые 2 с |
| `TestDetectsSyntheticIceberg` | 6 циклов пополнения bid-уровня 500/250 ед. |
| `TestDetectsSyntheticMarginLiquidation` | 12 продаж с ростом размера и падением цены в окне 14:00–14:30 МСК |
| `TestNoFalsePositiveOnShuffledTape` | перемешанная лента (клипы сохранены, расписание разрушено) → нет отпечатков с Confidence ≥ 0,3 |
| `TestSynthesizeContracts` | порядок ленты, сохранность базы, уникальные номера сделок |
| `TestMarginCallWindowParsing` | дефолтные окна и парсер `"HH:MM-HH:MM"` |
| `TestDetectEmptyAndCancelled`, `TestDetectDeterministic` | пустой вход, отмена контекста, детерминизм |

**Не проверено (I):** параметры подобраны на синтетике; реальные пороги (доля клипов, CV интервалов,
поведение на разреженной ленте) требуют записи Task 11 и ручной разметки. Окна маржин-коллов не
подтверждены. Никакого живого прогона в задаче не было.

## 5. Инструмент агента `detect_execution_algos`

```json
{"symbol": "TQBR:SBER", "from": "2026-11-05T07:00:00Z", "to": "2026-11-05T07:10:00Z",
 "marginCallWindows": ["14:00-14:30"]}
```

Возвращает компактный для модели результат (до `maxExecutionFootprints` отпечатков: kind, side,
from/to, confidence, evidence) и artifact `execution_algos` для UI. Источник ленты — необязательный
интерфейс `agent.LOBDataSource` (реализуется на `e.data`): пока проводка
`md.book_events`/`md.trades` в `cmd/terminal` не сделана (**I**, отложено на T18/T26), инструмент
возвращает понятную ошибку конфигурации; в тестах используется фейк. Живой источник не проверялся.
