# TRANSAQ: справочники (RQ_STARTUP) и инструменты (R_SEC_NEW)

Дата: 3 ноября 2026. Источник: `txmlconnector64-6.47.2.26.4.dll`, демо-сервер Finam. Обозначения статусов те же, что в [connect.md](connect.md): **S** — сверено с XML-колбэками DLL на демо-сервере, **D** — прочитано в декомпиляторе, **I** — вывод.

Реализация: [`internal/xmlcompat`](../../internal/xmlcompat). XML строится в структуры [`client/commands`](../../client/commands/main.go), которые уже используют клиенты.

## Методика

DLL под Wine подключалась к демо-серверу через логирующий прокси, harness сохранял все колбэки целиком. Каждая запись разобрана по декомпилированному обработчику и сверена с колбэком DLL из той же сессии. Справочники проверены побайтно, инструменты — по значениям полей.

## RQ_STARTUP

Ответ — шесть секций подряд в порядке вызовов из `FUN_180357e00`. Каждая секция завершается маркером `-1`. Разбор поглощает ответ демо-сервера (4355 байт) ровно до конца — **S**.

| Секция | Функция | Запись | Конец |
|---|---|---|---|
| рынки | `FUN_1803953e0` | `B:id Z10:код Z24:имя B B B B` | `B:0xff W` |
| типы режимов | `FUN_180395820` | `B:id Z32:имя Z8 B` | `B:0xff` |
| режимы (boards) | `FUN_180395b40` | `W:номер B:рынок Z7:код Z30:имя W B Z8 B B:тип` | `W:0xffff` |
| типы бумаг | `FUN_180395f70` | `B:id Z10 Z24 B B B` | `B:0xff` |
| виды свечей | `FUN_1803b88b0` | `B:id Z12:имя L:период L` | `B:0xff` |
| колонки | `FUN_1803b7ee0` | `B:id B Z32:заголовок Z16:код` | `B:0xff` |

Строки — CP1251. Правила формирования XML (совпадение с DLL **побайтно**, **S**):

- `<markets>`: `id` и **код** рынка (`ММВБ`, `FORTS`), отсортированные по `id`.
- `<boards>`: порядок как в ответе. Рынок 5 (опционы FORTS) DLL выводит как 4 — **D** (`FUN_1800c07f0`), **S**.
- `<candlekinds>`: порядок как в ответе.

## Записи RQ_MAIN

Ответ RQ_MAIN — поток записей `B:тег …`. Диспетчер — `FUN_18038d7d0`, в `switch` значение равно `тег−1`.

- У 12 тегов после тега идёт размер `W` (BE): 0x02 R_CLN_NEW, 0x03 R_ORD_NEW, 0x04 R_TRD, 0x08 R_ALLTRADE, 0x10 R_ORD_MODIFY, 0x28 R_SEC_NEW, 0x3a R_ORD_RENEW, 0x3b R_CLIENT_ASSET, 0x54 R_STOP, 0x5e R_SEC_PARAM, 0x5f R_WRAPPER, 0x66 R_DOUBLELEG. Перед каждым следующим тегом DLL переходит на конец записи, поэтому такие записи можно пропускать — **D**.
- Обёртка R_WRAPPER (0x5f) задаёт границу, а внутри идут обычные записи.
- Остальные ~70 тегов размера не имеют, и для разбора потока нужен формат каждого. Реализован R_DATE (0x3d, `L` — секунды на 00:00 дня торгов) — **S**.
- Снапшот демо-сервера: R_DATE, 17 176 × R_SEC_NEW, 17 176 × R_SEC_PARAM, 5 × R_DOUBLELEG. Затем идёт 0x62 с данными счёта (формат не разобран).

## R_SEC_NEW (0x28)

Обработчик — `FUN_180398640`. Все 17 176 записей демо-сервера разбираются без остатка до границы записи — **S**.

```
W:secid  B:рынок  B:вид  B:класс  Z25:seccode  Z30:shortname  Z12:ISIN
B  L  B:флаги (0x30 — call/put)  L
[вид 4|5: B:флаги производного; если &0x0c — Z25:базовый актив]
B:свойства
повторять до W:0xffff — параметры режима (pit):
    W:номер режима  L:лот  L:делитель лота  L:шаг (в 10^-decimals)  B:decimals  B
    D:point_cost (double LE)  Z12  B:режим по умолчанию  L  Z4:валюта расчётов
Z4:валюта
необязательно, пока не кончилась запись: B B | L + 16 байт пояса | Z5:MIC Z25:ticker | L L Z25 Z6 | B
```

`L:делитель лота` есть при версии протокола сервера > 0x42 (демо: 68) — **D**.

Отображение в `<security>` (совпадение со всеми 17 176 инструментами DLL, **S**):

| Поле XML | Источник |
|---|---|
| `secid`, `seccode`, `shortname` | одноимённые поля |
| `instrclass` | символ `класс`; при 0 — по виду бумаги: 0 E, 1 B, 4 F, 5 O, 7 I, 15 C, 16 S |
| `market` | рынок; 5 → 4 |
| `sectype` | по виду бумаги: 0 SHARE, 1 BOND, 4 FUT, 5 OPT, 7 IDX, 14 MCT, 15 ETS_CURRENCY, 16 ETS_SWAP |
| `board` | код режима, у которого стоит флаг «по умолчанию» (по номеру из RQ_STARTUP) |
| `decimals`, `lotdivider` | из режима по умолчанию |
| `lotsize` | лот режима по умолчанию; на FORTS (рынки 4, 5) всегда 1 |
| `minstep` | шаг × 10^-decimals; печатается с `decimals` знаками без хвостовых нулей, минимум одна цифра после точки (`0.01`, `1.0`) |
| `point_cost` | double, 6 значащих цифр (`%g`): `161.1146` → `161.115` |
| `currency` | валюта бумаги; пустая на рынке 1 → `RUR` |
| `currencyid` | валюта режима, иначе валюта бумаги; `RUR` → `RUB` |

## Что не разобрано

- `active`, `opmask`, `quotestype`, `sec_tz`, `MIC`, `ticker`. По генератору `FUN_18011f4a0`: флаги opmask собираются в `FUN_180398640` из таблицы типов бумаг RQ_STARTUP и байта свойств записи, а `sec_tz` — по 16-байтовому поясу. Это следующий шаг. В Go эти поля пока пустые.
- DLL закрывает `<ticker>` тегом `<ticker>` вместо `</ticker>` (`FUN_18011f4a0`) — **D**. На демо тикеров нет. Реализации не нужно воспроизводить эту ошибку, но на неё стоит рассчитывать при сравнении.
- `<pits>`, `<sec_info_upd>` (R_SEC_PARAM), R_DOUBLELEG, 0x62 и другие теги без размера.
- Подключение `internal/xmlcompat` к `connector.Connector`.

## Воспроизведение

```sh
go test ./internal/xmlcompat
# полная сверка на локальном захвате (вне репозитория):
TXML_DEMO_MAIN=main.hex TXML_DEMO_XML=dll.xml go test -run SecuritiesFull -v ./internal/xmlcompat
```

Фикстуры в `internal/xmlcompat/testdata` — справочные данные демо-сервера без полей счёта: ответ RQ_STARTUP, первый ответ RQ_MAIN (499 инструментов) и соответствующие колбэки DLL.
