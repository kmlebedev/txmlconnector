# TRANSAQ: подписка на сделки (alltrades) и вывод в NATS

Дата: 4 ноября 2026. Источник: `txmlconnector64-6.47.2.26.4.dll`, демо-сервер Finam. Статусы: **S** — проверено на демо-сервере, **O** — сверено с DLL через оракул (ниже), **D** — прочитано в декомпиляторе, **I** — вывод.

Реализация:
- [`native.Client`](../../native/client.go) — типизированный клиент без XML: подписка по `board`/`seccode`, сделки в виде `native.Trade`.
- [`native.Connector`](../../native/connector.go) — `subscribe`/`unsubscribe` с `<alltrades>` и колбэк `<alltrades>` как у DLL.
- [`native/natsout`](../../native/natsout/natsout.go) и [`tools/native-trades`](../../tools/native-trades/main.go) — публикация в NATS Core.

## Методика

1. DLL под Wine подписывалась на сделки на демо-сервере через логирующий прокси: TQBR SBER, GAZP, VTBR, LKOH; FUT SiZ6, RIZ6, BRZ6, CNYRUBF, USDRUBF. Так получены реальные `RQ_SUBSCRIBE` — **S**. Сделок демо-сервер вечером 3 ноября не прислал ни DLL, ни Go-клиенту.
2. Формат `R_ALLTRADE` восстановлен по `FUN_1803bf700` (сообщения DLL называют его `NEW_MTRADE`) — **D**.
3. **Оракул.** Фейк-сервер проигрывает DLL записанную реальную сессию: логин, справочники, снапшот, ответ на подписку. Сессионный ключ берётся из записанного ответа RQ_PWD. После `RQ_SUBSCRIBE` фейк-сервер подмешивает в RQ_MAIN сконструированные записи `R_ALLTRADE`. Выданный DLL `<alltrades>` показывает, как она понимает каждое поле. Три набора записей и ответы DLL лежат в `native/records/testdata/alltrades-*`, и Go воспроизводит эти ответы побайтно — **O**.

## RQ_SUBSCRIBE (10)

Запрос — **S**, **D** (`FUN_180359140`). Для каждой бумаги: `W secid`, `W номер режима` (из RQ_STARTUP: TQBR = 37, FUT = 42), `B маска`. Маска — полное желаемое состояние подписки этой бумаги:

| Бит | Подписка | Статус |
|---|---|---|
| `0x01` | `<quotations>` | **S** (живые прогоны r8/r9: маска 1 — только котировки; 5 = сделки+котировки; 0 — отписка). **D**: `FUN_180359140` считает биты 0x01/0x02/0x04 из `FUN_1801dbd40`/`FUN_1801dbde0`/`FUN_1801dbe80` и пишет `W secid, W board, B mask` |
| `0x02` | `<quotes>` | **S** (r10: mask 0x02 → GAZP/SiZ6/HYDR; 0x06 = alltrades+quotes → SBER; 0 при отписке). **D**: бит считается через `FUN_1801dbde0` в `FUN_180359140` |
| `0x04` | `<alltrades>` | S |

Несколько бумаг в одной команде `subscribe` с несколькими элементами `<quotations>` DLL не
разбирает: команда вернула success=true, но RQ_SUBSCRIBE/RQ_SEC_SPEC ушли только для первой
бумаги — **S** (r8); в r9 подписки шли отдельными командами и принялись все.

Отписка — та же бумага с маской без бита, при пустой подписке маска 0 — **S**. Ответ сервера — пустой payload с флагом `0x82`. Данные затем идут через RQ_MAIN. После подписки DLL дополнительно шлёт `RQ_SEC_SPEC` (15) со списком `W secid`; Go-клиенту он не нужен.

`secid` стабилен только внутри сессии, поэтому клиент сопоставляет `(board, seccode)` → `secid` по записям `R_SEC_NEW` из снапшота (`records.Catalog`).

## Записи RQ_MAIN после подписки

Кроме размерных записей, после подписки идут обновления атрибутов бумаг без размера (`FUN_1803c1360`) — **D**, **S**:

| Тег | Имя | Тело |
|---|---|---|
| `0x0a` | R_SEC_RATE | `W secid`, `L` |
| `0x0b` | R_SEC_ZALOG | `W secid`, `B` |
| `0x0c` | R_SEC_OBLIG | `W secid`, `B` |
| `0x0d` | R_SEC_ONOFF | `W secid`, `B` |
| `0x0e` | — | `W secid`, `B` |

Без них поток не прочитать дальше первой такой записи. На демо-сервере после подписки разбирается 100% ответов. Единственная неразобранная запись за сессию — `0x62` в конце снапшота, данные счёта.

## R_ALLTRADE (0x08, с размером)

```
W secid  W режим  G tradeno  L время  L цена  L количество  W флаги
флаги, в порядке чтения:
  0x0001  B  period         → <period>
  0x0002  L                 (в <alltrades> не выводится)
  0x0004  G                 (в <alltrades> не выводится)
  0x0002  G                 (второе поле флага 0x0002)
  0x0008  B  buysell        → <buysell>, только 'B'/'S'
  0x0010  Z12               (в <alltrades> не выводится)
  0x0020  L L G G           (в <alltrades> не выводится)
  0x0040  L  open interest  → <openinterest>
  0x0080  Z4                (в <alltrades> не выводится)
  0x0100  W  миллисекунды   (1000 = нет)
```

`G` — 64-битное упакованное целое (`FUN_1801bd9b0`): как `L`, но счётчик 7 означает 8 дополнительных байт — **D**, **O**.

Смысл полей — **O**:
- `время` — секунды «настенного» времени сервера как Unix time. Без времени (0) DLL ставит 00:00 дня торгов (`R_DATE`). Go-клиент переводит в UTC по смещению из блока часового пояса RQ_TIME (−180 мин для МСК): 23:53:20 МСК → 20:53:20 UTC.
- `цена` — со знаком, в единицах 10^-decimals режима сделки. DLL печатает её как `minstep`: без хвостовых нулей, но с одной цифрой после точки (`305.0`).
- DLL отбрасывает сделку, если её номер не больше последнего по этой бумаге и режиму, с записью в журнале `TQBR:SBER old ALLTRADE No:…`. Так же делает `records.TradeDedup`.
- Флаги `0x02`, `0x04`, `0x10`, `0x20`, `0x80` DLL читает, но в `<alltrades>` не выводит. Их смысл не установлен; клиент отдаёт их в `Trade.Raw` (`model.AllTrade`, заполняет декодер в `native/records`).

## R_QUOTATION (0x06) и `<quotations>`

PDF 4.7; обработчик `FUN_1803bc2f0`, XML-строитель — большой генератор `FUN_1800f7b40`
(литерал `<quotations>` — `0x1800fa16f`), отправка `FUN_1800dba90`.

**Формат записи — D, S.** Запись безразмерная: `W secid`, `W board`, `G mask` (64-битная,
wide packed `FUN_1801bdb90`), далее по одному `L`-значению (`FUN_1801bd7b0`) на каждый
установленный бит маски, в порядке возрастания номера бита. Номер поля → слот: `FUN_180263d60`,
`FUN_180255880`; сравнение с предыдущим состоянием `FUN_18026c4c0`; событие в очередь
`FUN_1802aad00(ctx+0x100, secid|0xa0000)`.

**В `<quotations>` приходят только изменившиеся поля — S**: в r9 обновления HYDR/MCT несли 1–2
поля, а первое событие после подписки — полный набор (31 значение маски). Колбэк:
`<quotations><quotation secid="N"><board>…</board><seccode>…</seccode>` + поля +
`</quotation></quotations>`.

**Карта бит маски → поля `<quotations>` (S значения, D номера;** проверено 99 полей / 0 расхождений
с DLL на 16 живых событиях):**

| Бит | Поле | Формат |
|---|---|---|
| 0/2 | `biddeptht` / `offerdeptht` | int |
| 1/3 | `numbids` / `numoffers` | int |
| 4/5 | `biddepth` / `offerdepth` | int |
| 6/7 | `bid` / `offer` | цена: `v / 10^decimals` (хвостовые нули срезаны, минимум 1 знак) |
| 8/9 | `numtrades` / `voltoday` | int |
| 10 | `openpositions` | int (фьючерсы) |
| 12 | `quantity` | int |
| 13 | `time` | v < 86400 — секунды дня → `HH:MM:SS`; иначе Unix-время → `dd.mm.yyyy HH:MM:SS` (S; правило — I) |
| 14/15/16 | `last` / `change` / `priceminusprevwaprice` | цена (15/16 знаковые) |
| 18 | `valtoday` | `v / 1000` |
| 20 | `waprice` | цена |
| 26/27/28/29/30/31 | `highbid`/`lowoffer`/`high`/`low`/`open`/`closeprice` | цена |
| 33/34 | `status` / `tradingstatus` | байт → символ (A, N/T/0) |
| 42 | `lcurrentprice` | цена (бит 41 в тех же масках не выводится) |
| 54/55 | `buydeposit` / `selldeposit` | `v / 100` |

Биты 17, 39, 40, 41, 56, 59 DLL читает, но в `<quotations>` не печатает — **I** (вероятно,
`accruedintvalue`, `yield`/`yieldatwaprice`, `marketpricetoday`, `theoreticalprice`, `bgo_buy`,
`point_cost`; сверять с PDF 4.7). Остальные биты на демо не встречались.

`decimals` берётся из режима бумаги (pit в R_SEC_NEW): SiZ6/RIZ6/FUT — 0, GAZP/TQBR — 2,
HYDR/TQBR — 4, HYDR/MCT — 2 — **S**. Форматирование цены — как у `minstep` DLL: без хвостовых
нулей, минимум одна цифра после точки; при decimals=0 — целое.

**RE-3 (разные decimals у одной бумаги) — S:** HYDR в двух режимах в одном прогоне — TQBR
(board 37, decimals 4, secid 2; `last=0.4968`, `bid=0.496`) и MCT (board 45, decimals 2,
secid 8326; `last=35.9`, `bid=35.62`). Сырое значение одного и того же бита 6: 4960 → 0.496
и 3562 → 35.62; пара пригодна для `TestQuotationUsesBoardDecimals`.

**Живые фикстуры (RE-2, 2026-11-04):** `native/records/testdata/quotation-live.hex` (16 записей
0x06 подряд, 429 байт) + `quotations-dll.xml` (те же 16 колбэков в порядке выдачи) +
`quotation-live.md` (прогоны, карта, RE-3, как использовать). Подписки: маска 0x01 для SBER,
SiZ6, RIZ6, GAZP, HYDR TQBR и HYDR MCT; 16 записей ↔ 16 колбэков (secid 1:1) — S.

Не разобрано/не проверено: смысл невыводимых битов; маска `0x02` (`<quotes>`) живьём не
наблюдалась; правило выбора Unix-времени вместо секунд дня у MCT; влияние `utc_time`/
`milliseconds` на `time` (нужны колбэки с подпиской на эти опции).

## R_QUOTES (0x07) и `<quotes>`

PDF 4.9; обработчик `FUN_1803bdc40` (`"BOOK: …"`), хранилище уровней `FUN_180255600`,
XML-строитель — `FUN_1800f7b40` (литералы `<quotes>` — `0x180836848`, `<quote secid="` — `0x180836858`).

**Формат записи — D, S.** Запись безразмерная:

```
W secid; W board;
loop: B side            ; 'B' = buy, 'S' = sell; 0xFF — конец записи
      L price_delta     ; дельта к предыдущей цене; абсолютная цена = накопленная сумма,
                        ; накопление продолжается и при переходе B -> S
      L quantity        ; объём уровня
```

Пример (GAZP): `42 32bc02 c112` = `B`, δ=11203 (112.03 от 0), qty=300; `42 18 428502` = `B`,
δ=−1 (112.02), qty=10324; `53 e010` = `S`, δ=+14 (112.08), qty=1. Все уровни одного снимка
идут в одном `<quotes>` (сначала buy, затем sell): `<quote secid="N"><board>…</board>`
`<seccode>…</seccode><price>…</price><yield>…</yield><buy|sell>…</buy|sell></quote>`; цена —
по `decimals` режима (TQBR — 2).

**Живой прогон r10 (2026-11-04, S):** подписки `<quotes>` дали маски RQ_SUBSCRIBE `0x02` для
GAZP (board 37), SiZ6 (42), HYDR/MCT (45) и `0x06` (alltrades+quotes) для SBER; RQ_SEC_SPEC
подтвердил принятые secid. Пришло 2 записи 0x07 (GAZP, SBER) и 2 колбэка `<quotes>`;
разбор дал 20+20 уровней, **40/40 совпали с XML DLL** по стороне, цене и объёму — S.
Стакан приходит полным снимком при подписке; инкрементальных обновлений за ~85 с не было —
S (вечерняя сессия/демо). Подписка SBER quotes-only сразу после загрузки вернула
`success="false"` («Cannot process this command wi…»), позже combined-подписка 0x06 принялась.

**Не проверено (I):** удаление уровня (в обработчике при накопленной цене < 1 существующий
уровень помечается `+0x40 = 2`, лог `SignPrice set`; живьём не наблюдалось); необязательное
поле `L` между ценой и объёмом (читается при `FUN_18024f280(ctx, secid) != 0`, в XML —
`<yield>`; для TQBR-бумаг демо флаг 0, `<yield>0</yield>` — значение по умолчанию); вариант
`<quote>` с `<source>` (литералы `0x180836978`/`0x1808369f8`) — для каких режимов неизвестно.

**Фикстуры (RE-2):** `native/records/testdata/quote-live.hex` (174 байта — 2 записи 0x07 подряд)
+ `quotes-dll.xml` (2 колбэка) + `quote-live.md` (прогон, разбор, использование).

## Вывод в NATS Core

`tools/native-trades` подключается без DLL, подписывается и на каждую сделку публикует protobuf [`marketdata.Trade`](../../proto/marketdata/trade.proto) в тему `<prefix>.<board>.<seccode>` (по умолчанию `transaq.alltrades`). Символы `.`, `*`, `>` и пробелы в токенах заменяются на `_`.

```sh
TC_LOGIN=... TC_PASSWORD=... go run ./tools/native-trades \
  -addr tr1.finam.ru:3900 -nats nats://127.0.0.1:4222 -sec TQBR:SBER,FUT:SiZ6
```

| Поле | Тип | Значение |
|---|---|---|
| `board`, `seccode` | string | стабильный ключ бумаги |
| `tradeno` | int64 | биржевой номер сделки |
| `time_ms` | int64 | Unix мс, UTC |
| `price`, `decimals` | sint64, uint32 | точная цена `price × 10^-decimals`, без float |
| `quantity` | int64 | количество |
| `side` | enum | BUY / SELL / UNSPECIFIED |
| `period` | uint32 | символ периода (`O`, `N`, `C`) или 0 |
| `open_interest` | optional int64 | для фьючерсов и опционов |
| `secid` | uint32 | только внутри сессии |

Сообщение сделки занимает 35–39 байт; XML-сделка DLL — около 230 байт.

Проверено:
- `native/natsout` — юнит-тестом;
- вся цепочка — вручную: `nats-server` 2.15.2, `native-trades` против проигрываемой реальной сессии с подмешанными сделками и подписчик, расшифровавший все пять protobuf-сообщений в правильных темах — **O**;
- на демо-сервере `native-trades` подключается, сервер принимает `RQ_SUBSCRIBE`, поток после подписки разбирается, по `SIGINT` уходит `RQ_LOGOUT` — **S**.

## Что не доказано

- Живые сделки с сервера: демо-сервер вечером 3 ноября их не прислал, и проверить можно будет в основную сессию (5 ноября после 10:00 МСК). Формат проверен через DLL на сконструированных записях, а не на реальном потоке.
- Смысл флагов `0x02`, `0x04`, `0x10`, `0x20`, `0x80` и бит `0x02` маски (`quotes`).
- Переподключение: при потере связи `native-trades` завершается, перезапуск — за супервизором. После перезапуска `secid` пересчитываются, и подписка восстанавливается заново.
- Стакан (`quotes`, тег `0x07`): формат и фикстуры восстановлены (см. раздел выше), реализация — задача 10. Не проверено: инкрементальные обновления стакана (живьём приходил только полный снимок при подписке), удаление уровня, необязательное поле `<yield>`/`<source>`.
