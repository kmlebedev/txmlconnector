# TRANSAQ: подписка на сделки (alltrades) и вывод в NATS

Дата: 4 ноября 2026. Источник: `txmlconnector64-6.47.2.26.4.dll`, демо-сервер Finam. Статусы: **S** — проверено на демо-сервере, **O** — сверено с DLL через оракул (ниже), **D** — прочитано в декомпиляторе, **I** — вывод.

Реализация:
- [`native.Client`](../../native/client.go) — типизированный клиент без XML: подписка по `board`/`seccode`, сделки в виде `native.Trade`.
- [`native.Connector`](../../native/connector.go) — `subscribe`/`unsubscribe` с `<alltrades>` и колбэк `<alltrades>` как у DLL.
- [`native/natsout`](../../native/natsout/natsout.go) и [`tools/native-trades`](../../tools/native-trades/main.go) — публикация в NATS Core.

## Методика

1. DLL под Wine подписывалась на сделки на демо-сервере через логирующий прокси: TQBR SBER, GAZP, VTBR, LKOH; FUT SiZ6, RIZ6, BRZ6, CNYRUBF, USDRUBF. Так получены реальные `RQ_SUBSCRIBE` — **S**. Сделок демо-сервер вечером 3 ноября не прислал ни DLL, ни Go-клиенту.
2. Формат `R_ALLTRADE` восстановлен по `FUN_1803bf700` (сообщения DLL называют его `NEW_MTRADE`) — **D**.
3. **Оракул.** Фейк-сервер проигрывает DLL записанную реальную сессию: логин, справочники, снапшот, ответ на подписку. Сессионный ключ берётся из записанного ответа RQ_PWD. После `RQ_SUBSCRIBE` фейк-сервер подмешивает в RQ_MAIN сконструированные записи `R_ALLTRADE`. Выданный DLL `<alltrades>` показывает, как она понимает каждое поле. Три набора записей и ответы DLL лежат в `native/records/testdata/alltrades-*`, и Go воспроизводит эти ответы побайтно — **O**.

## RQ_SUBSCRIBE (10)

Запрос — **S**, **D** (`FUN_180359140`). Для каждой бумаги: `W secid`, `W номер режима` (из RQ_STARTUP: TQBR = 37, FUT = 42), `B маска`. Маска — полное желаемое состояние подписки этой бумаги:

| Бит | Подписка | Статус |
|---|---|---|
| `0x04` | `<alltrades>` | S |
| `0x01` | `<quotations>` | S (маска 5 = сделки + котировки) |
| `0x02` | `<quotes>` | I |

Отписка — та же бумага с маской без бита, при пустой подписке маска 0 — **S**. Ответ сервера — пустой payload с флагом `0x82`. Данные затем идут через RQ_MAIN. После подписки DLL дополнительно шлёт `RQ_SEC_SPEC` (15) со списком `W secid`; Go-клиенту он не нужен.

`secid` стабилен только внутри сессии, поэтому клиент сопоставляет `(board, seccode)` → `secid` по записям `R_SEC_NEW` из снапшота (`records.Catalog`).

## Записи RQ_MAIN после подписки

Кроме размерных записей, после подписки идут обновления атрибутов бумаг без размера (`FUN_1803c1360`) — **D**, **S**:

| Тег | Имя | Тело |
|---|---|---|
| `0x0a` | R_SEC_RATE | `W secid`, `L` |
| `0x0b` | R_SEC_ZALOG | `W secid`, `B` |
| `0x0c` | R_SEC_OBLIG | `W secid`, `B` |
| `0x0d` | R_SEC_ONOFF | `W secid`, `B` |
| `0x0e` | — | `W secid`, `B` |

Без них поток не прочитать дальше первой такой записи. На демо-сервере после подписки разбирается 100% ответов. Единственная неразобранная запись за сессию — `0x62` в конце снапшота, данные счёта.

## R_ALLTRADE (0x08, с размером)

```
W secid  W режим  G tradeno  L время  L цена  L количество  W флаги
флаги, в порядке чтения:
  0x0001  B  period         → <period>
  0x0002  L                 (в <alltrades> не выводится)
  0x0004  G                 (в <alltrades> не выводится)
  0x0002  G                 (второе поле флага 0x0002)
  0x0008  B  buysell        → <buysell>, только 'B'/'S'
  0x0010  Z12               (в <alltrades> не выводится)
  0x0020  L L G G           (в <alltrades> не выводится)
  0x0040  L  open interest  → <openinterest>
  0x0080  Z4                (в <alltrades> не выводится)
  0x0100  W  миллисекунды   (1000 = нет)
```

`G` — 64-битное упакованное целое (`FUN_1801bd9b0`): как `L`, но счётчик 7 означает 8 дополнительных байт — **D**, **O**.

Смысл полей — **O**:
- `время` — секунды «настенного» времени сервера как Unix time. Без времени (0) DLL ставит 00:00 дня торгов (`R_DATE`). Go-клиент переводит в UTC по смещению из блока часового пояса RQ_TIME (−180 мин для МСК): 23:53:20 МСК → 20:53:20 UTC.
- `цена` — со знаком, в единицах 10^-decimals режима сделки. DLL печатает её как `minstep`: без хвостовых нулей, но с одной цифрой после точки (`305.0`).
- DLL отбрасывает сделку, если её номер не больше последнего по этой бумаге и режиму, с записью в журнале `TQBR:SBER old ALLTRADE No:…`. Так же делает `xmlcompat.TradeDedup`.
- Флаги `0x02`, `0x04`, `0x10`, `0x20`, `0x80` DLL читает, но в `<alltrades>` не выводит. Их смысл не установлен; клиент отдаёт их в `Trade.Raw`.

## Вывод в NATS Core

`tools/native-trades` подключается без DLL, подписывается и на каждую сделку публикует protobuf [`marketdata.Trade`](../../proto/marketdata/trade.proto) в тему `<prefix>.<board>.<seccode>` (по умолчанию `transaq.alltrades`). Символы `.`, `*`, `>` и пробелы в токенах заменяются на `_`.

```sh
TC_LOGIN=... TC_PASSWORD=... go run ./tools/native-trades \
  -addr tr1.finam.ru:3900 -nats nats://127.0.0.1:4222 -sec TQBR:SBER,FUT:SiZ6
```

| Поле | Тип | Значение |
|---|---|---|
| `board`, `seccode` | string | стабильный ключ бумаги |
| `tradeno` | int64 | биржевой номер сделки |
| `time_ms` | int64 | Unix мс, UTC |
| `price`, `decimals` | sint64, uint32 | точная цена `price × 10^-decimals`, без float |
| `quantity` | int64 | количество |
| `side` | enum | BUY / SELL / UNSPECIFIED |
| `period` | uint32 | символ периода (`O`, `N`, `C`) или 0 |
| `open_interest` | optional int64 | для фьючерсов и опционов |
| `secid` | uint32 | только внутри сессии |

Сообщение сделки занимает 35–39 байт; XML-сделка DLL — около 230 байт.

Проверено:
- `native/natsout` — юнит-тестом;
- вся цепочка — вручную: `nats-server` 2.15.2, `native-trades` против проигрываемой реальной сессии с подмешанными сделками и подписчик, расшифровавший все пять protobuf-сообщений в правильных темах — **O**;
- на демо-сервере `native-trades` подключается, сервер принимает `RQ_SUBSCRIBE`, поток после подписки разбирается, по `SIGINT` уходит `RQ_LOGOUT` — **S**.

## Что не доказано

- Живые сделки с сервера: демо-сервер вечером 3 ноября их не прислал, и проверить можно будет в основную сессию (5 ноября после 10:00 МСК). Формат проверен через DLL на сконструированных записях, а не на реальном потоке.
- Смысл флагов `0x02`, `0x04`, `0x10`, `0x20`, `0x80` и бит `0x02` маски (`quotes`).
- Переподключение: при потере связи `native-trades` завершается, перезапуск — за супервизором. После перезапуска `secid` пересчитываются, и подписка восстанавливается заново.
- Котировки (`quotations`, тег `0x06`) и стакан (`quotes`) не реализованы.
