# change_pass: RQ_CHANGE_PWD (3) — формат, ответы, ограничения (Task 26)

Дата: 2026-11-05. Источник: RE-1 (декомпилятор DLL 6.47.2.26.4) + RE-3 (оракул: replay-server +
DLL под Wine, только loopback). Статусы: **S** — демо-сервер, **O** — оракул DLL, **D** —
декомпилятор, **I** — вывод.

> **Ограничение безопасности.** Живая смена пароля на реальном сервере **запрещена** (карточка
> task-57 и AGENTS §6): все O-прогоны — DLL против записанной сессии на loopback, пароли
> синтетические. Реальный пароль не снимался и не печатался.

## Команда (D + O)

`<command id="change_pass" oldpass="…" newpass="…"/>` — оба **атрибута** обязательны
(`FUN_18040cf20`). Обработчик `FUN_180197fe0` → `FUN_1800ebf70`; отправитель
`FUN_180384c40` → `FUN_1803b18d0` (RQ_CHANGE_PWD, тип 3).

### Локальные проверки до отправки (D + O, дословные тексты)

| Условие | Текст ошибки |
|---|---|
| нет/пустой `oldpass` | `You have to specify old password` |
| нет/пустой `newpass` | `You have to specify new password` |
| длина пароля > 20 | `Password cannot be longer than 20 characters.` |
| в новом пароле символ `;` | `Forbiden character: ';'` (опечатка DLL: «Forbiden»; в XML сообщение приходит с двойным экранированием кавычек — O) |
| новый == старый | `The same passwords specified` |
| политика безопасности сервера включена (conn+0x279 == 1) и пароль не проходит проверку (длина ≥6, англ. буква, цифра, спецсимвол, соседние символы различаются) | длинный текст `Specified password doesn't satisfy sequrity requirements: …` (D; в oracle-прогонах флаг политики 0 — проверка не срабатывала, слабый пароль ушёл) |
| не удалось отправить | `RQ_CHANGE_PWD send failed` (D) |

## Запрос RQ_CHANGE_PWD (3) — 56 байт (D + O)

```
SHA-1(oldpass)          20 байт
0x00 × 8                (зарезервировано; назначение — I)
SHA-1(newpass)          20 байт
0x00 × 8                (зарезервировано; назначение — I)
```

- D: `FUN_1801bc080` = SHA-1 пароля (`FUN_1801bc000` → hash init/update/final) + 12-байтовая
  добивка `FUN_18043d370`; в провод пишутся первые 20 байт (`FUN_1801be5d0`), затем 8 байт
  структуры (`+0x14`), затем то же для нового (`+0x1c`, `+0x30`); отправка
  `FUN_180355d50(...,3,"RQ_CHANGE_PWD")`.
- O: payload побайтно = SHA-1 синтетических паролей + нули (сверено в Python:
  `sha1("OldPass2!") == 42c124f7…7ef4`, `sha1("TestPass1!") == 79596833…6861`).
- **Пароли передаются несолёным SHA-1** (без random/соли) — свойство DLL; для Go-реализации
  требуется для совместимости (это I-риск безопасности, зафиксирован).
- Транспортный кадр шифруется сессионным ключом как остальные запросы (O: payload в дампе после
  расшифровки; форма кадра — `native/wire`).

## Ответ (D + O)

Ответ — прямой reply-кадр type=3: `B status`, при `status==2` далее C-строка текста
(`FUN_1801bd170`, до 0xfff0 байт):

| status | Поведение DLL (O) |
|---|---|
| 0 | `<result success="true"/>` |
| 1 | `<result success="false"><message>Wrong oldpass specified.</message></result>` |
| 2 + текст | `<result success="false"><message>&lt;текст&gt;</message></result>` |
| пустой reply | фатально: D-лог `RQ_CHANGE_PWD incorrect server buffer`, соединение закрывается (`connected="false"`) — **O** |

Прочие значения status — не проверялись (**I**; по коду: «else» → текст из структуры, может быть
пустым).

## Сессия/recover после успеха — I

- Хендлер не трогает сессионные ключи и «recover»-ключ задачи 5 (D: после `FUN_180384c40`
  только возврат кода; обновления ключей в обработчике нет).
- D: recover-ключ выводится из пароля при логине (`RQ_PWD`, `cryptoprofile.PasswordKey`);
  после успешной смены DLL, судя по коду, продолжает сессию со старыми ключами до следующего
  подключения. Требуется ли клиенту обновлять сохранённый пароль/recover-ключ — **I**
  (для Go API: после успеха вызывающий должен сам обновить свой конфиг; см. task-26 план).

## S-негатив / не проверено

- **S**: живая смена пароля запрещена; S-фактов нет намеренно.
- Политика безопасности (conn+0x279==1) в oracle-прогонах выключена — реальное поведение на
  демо-сервере (если политика включена) — **I**; проверять только с согласия пользователя.
- Точные условия включения флага политики (какой параметр `connect`/серверный флаг) — **I**.
- Поведение при status вне {0,1,2} — **I**.
